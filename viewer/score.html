Activity Score

「いま、どの repo が動いているか」を機械的に並べるためのスコアです。人手で選ぶランキングではなく、GitHub から観測できる活動を使って再現します。

← Active Repository Viewer

現在の基本式

score = 100 × exp(−ageDays / 14) + stars × 0.25 + openIssues × 0.35

ageDays は最後の push からの経過日数。時間が経つほど活動の基本点は指数的に下がります。

1. 最近 push されたか

現在のスコアで最も大きい要素です。直近に更新された repo ほど高くなります。

recency = 100 × exp(−ageDays / 14)
  • push 直後 → 約 100 点
  • 14 日後 → 約 36.8 点
  • 28 日後 → 約 13.5 点
  • 古い repo → 徐々に 0 に近づく

つまり「最近動いている」というシグナルを強く評価します。

2. Stars

+0.251 star あたりの加点
最大 +12.5現在は 50 stars まで加点

人気・外部からの関心を補助的なシグナルとして使います。活動の新しさより弱い重みです。

3. Open Issues

+0.35open issue 1 件あたり
最大 +10.5現在は 30 件まで加点

未解決の課題が多い repo を「活動中」とみなす補助指標です。issue が多いだけで上位になりすぎないよう上限を設けています。

Score の読み方

低い / 静的高い / 活発

絶対的な「repo の価値」ではありません。いま観測したときの活動度です。

  • 高スコア = 最近動いている可能性が高い
  • 低スコア = 最近の GitHub 活動が少ない可能性が高い
  • Stars や issue は補助指標
  • ランキングは観測時点で変化する

なぜ Score を作るのか

bonsai の repo は多数あります。全部を毎回人間が読むのではなく、まず活動度で Working Set を作ります。

bonsai/* → activity observation → score → top 30 → Working Set → AW / Coordinator

重要なのは「30 repo だけが組織」なのではなく、全 repo の中から現在の作業対象を動的に切り出すことです。

今後の拡張

この score は最初の単純な版です。将来的には GitHub の観測データと BQML の分析結果を組み合わせます。

  • commit frequency / development velocity
  • Pull Request activity
  • issue activity
  • repository health
  • dependency / capability relationships
  • BQML による自己組織化・クラスタリング

最終的には、Score は「価値」ではなく「現在の組織状態を観測するための信号」として扱います。

bonsai/latest · score is an observable activity signal, not a quality judgment.
